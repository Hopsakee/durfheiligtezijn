# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

A welcome game for a Catholic youth group (13-year-olds plus leaders). Each participant does a home quiz that matches them to a saint, picks one of three, and on the game afternoon the group guesses who has which saint. Design: `docs/design/plan-heiligen-welkomstspel.md` (decisions) and `docs/design/rubric.md` (axes, interests, matching formula). `ISA.md` is the state of record: which claims are closed, what is open. The code and the UI are Dutch.

## Commands

```bash
uv sync
uv run pytest -q                                   # all tests
uv run pytest -q tests/test_scoring.py::test_matchformule_met_de_hand_berekend   # one test (or -k "geslachtsfilter")
uv run python -m durfheilig.speel                  # play the quiz in the terminal, no web
uv run python -m durfheilig.simulatie              # regenerates docs/simulatie/rapport.md (seeded, reproducible)
uv run python -m durfheilig.dev                    # web app on 127.0.0.1:8000/dev, pick a kid or leader; reads .env
uv run python -m durfheilig.dev --dummies 12       # same, after 12 fake players played the quiz (no LLM); --schoon starts from an empty dev database; --lan also listens on the network (phones/tv) and /dev has a button that makes the dummies vote
python pipeline/merge_aanvulling.py FILE.json      # merge a saint supplement into data/heiligen.json
uv run e2e/escape.py                               # escape room end-to-end in headless Chromium (own dev server, free port); screenshots in e2e/screenshots/
```

`uv run --frozen ...` skips re-locking (needed in the offline sandbox that cannot reach PyPI); with a lock made against PyPI the box also needs `--no-sync` after `uv pip install -e . pytest` from its wheel store. `uv.lock` must be produced on a machine with PyPI access: a lock made offline points at `/opt/wheels`, and the `Dockerfile` refuses to build with it. Gemini is optional locally: copy `.env.example` to `.env` and fill `GEMINI_API_KEY` and `GEMINI_MODEL`; without them the app uses the fixed fallback texts.

## Architecture

- **Content is JSON in git, state is SQLite.** `data/heiligen.json` (the saints) and `data/vragen.json` (24 either-or questions plus the interest question) are loaded into memory by `data.py`, which validates every record and fails loudly. `data/heiligen-uitgevallen.json` holds saints dropped for having fewer than 4 of 6 known axes; it is never loaded. SQLite (`db.py`) holds only players, their answers and matches. Fix a text by editing the JSON and redeploying. Do not hardcode counts of saints in tests; derive them from the data.
- **Matching is deterministic first, LLM second** (`scoring.py`, `llm.py`). Answers give a profile on six axes (-2..+2) plus 2 or 3 interests; saints are ranked by a z-score of the match score against that saint's own distribution over all possible answer patterns, so saints with one interest or middling axes do not win for everyone. The top 12 go to the LLM twice (Gemini, or any OpenAI-compatible provider such as Scaleway: `llm_uit_omgeving` picks by `LLM_PROVIDER`, else by which variables are set; the key only goes over https; `Begrenzer` keeps the calls inside the account's tokens-per-minute and requests-per-second limits by queueing them, and a call that would wait longer than `LLM_MAX_WACHT` seconds goes straight to the fixed text): call 1 invents 3 follow-up either-or questions, call 2 picks 3 saints and writes a personal explanation. Both answers are validated against the candidate list, retried once, then replaced by a deterministic fallback, so a failing API never stops the game. Axis sign convention follows `rubric.md`, not the key name (for `samen_alleen` the minus pole is "alleen").
- **The web app is a step machine** (`app.py`). `invulling.stap` holds the step; every step is a plain form POST plus redirect, so a phone that locks or loses signal loses nothing. `ui.py` holds what every page shares (CSS, the page frame with its hamburger menu, image URLs, the leader groups) so `app.py` and `raadspel.py` never import each other. The login check in `app.py` is the one place that decides two things for every route: `/beheer` and everything under it is for leaders only, and a request that changes something must not come from another site; a new route cannot forget either. The menu is role-aware through a context variable set by that async check, and `/menu` is the start page; leaders land there at `/`, kids at `/` get their quiz (`/quiz` is the quiz for everyone). Routes answer GET only unless they say `methods=["post"]` (FastHTML otherwise also answers POST). A kid can undo the last answer (`/vraag/terug`) and fill the quiz in again (`/quiz/opnieuw`, refused once the game has started; the rule is checked inside the transaction in `db.reset_invulling`, and slow steps that waited for the LLM write only if the kid is still in the same step). Quiz order: welkom, voorkeur, 12 questions, interests, open answers, follow-up questions, choice of 3, thank-you. Slow steps (Gemini) mark their form with `data-laad` to show a loading cover. The guessing game on the afternoon is `raadspel.py` (points are per voter: 1 for being right in one of the two stemrondes, 3 for both, `punten_voor`/`score_ronde`; no majority, so no tie to settle; the leader ticks who takes part before the start; the tv ends with a scoreboard per subject and round, next to what random guessing would give): pure rules (board draw, majority, points) plus the routes for the phones (`/spel`), the tv and the leader's control page (`/beheer/tv`, `/beheer/spel`); screens poll every 2 seconds with htmx, and the game state lives in the `spel`, `bord`, `spelronde`, `stem` and `gelezen` tables. Never show who voted for what, and never show before the reveal which saint belongs to the current subject. Every round shows the whole board on phones, tv and the saint info page `/spel/heilige/{qid}`, whatever gender the subject asked for: the group must not learn that preference (a filtered board would show it). A vote card is one button (tap = vote) with a sibling ⓘ link; the info page is a page of its own because the voting screen refreshes every 2 seconds. A saint can be chosen once: a unique database constraint, and a lost race quietly gives that player a fresh top 3.
- **The escape room is a separate module** (`escape.py`, played 2026-10-25): two teams (A and B) in two rooms find five pieces of evidence; the screens show the race. Content in `data/escape.json` (`laad_escape` validates it and fails loudly: numbered 1..N, exactly 3 hints, no answer shared between puzzles, `cijfer` 0-9, one puzzle's `volgorde` exactly 3 distinct digit-bearing puzzles, since the padlocks have 3 dials (`SLOT_CIJFERS`); `slotcode` reads the lock code from them). State in the `escape_*` tables; group wipe and export cover them. Pure rules: `normaliseer`/`klopt` (lowercase letters and digits only), `speeltijd`/`team_stand` (time left = play time + leader's extra - 3 min per hint - time played without pauses; frozen at the finish), `nieuwe_extra` (minutes given after 0:00 count from now), `winnaar` (shortest time with penalties, once every team is done or out). The server computes every clock from stored epoch times (`maak_app(tijd=...)` fixes the time in tests). **Teams are accounts assigned by a leader**: each team phone uses an ordinary account (group `durfte`, never a leader, so the kids cannot reach `/beheer`); opening `/escape` puts the account in `escape_account` without a team and shows "Wacht op de recherche…", and the page reloads by itself once the leader assigns it at `/beheer/escape` (a polled block with `data-wacht`). Only an assigned non-leader account can answer or take hints, for its own team; leaders never can (`mijn_team` returns None for them), and a leader's `/escape` is a page of links. Usernames are never hardcoded. A non-leader account that is in `escape_account` (it opened `/escape` once, assigned or not) lands at `/` on the start page instead of the quiz, with two big buttons on top (📱 Teamtelefoon → `/escape`, 🖥️ Recherchebord → `/escape/bord`) and the same two first in its menu (`_teamaccount` in `ui.py`, looked up lazily like the profile); other kids see no change. The phone pages have no menu. Room laptops log in with the team account too (no leader login in a room with the kids) and show `/escape/bord`, the board of the account's own team (never chosen by the address; unassigned: the waiting screen); leaders watch the same board at `/beheer/escape/tv?team=A`. A room board gets the other team's events only as "found one" or "found all" (`gebeurtenissen(kamer)`): never its hints, wrong answers, evidence titles or dossier lines. The board is a corkboard where each piece of evidence lands as a post-it with its lock digit, tied by an SVG red string to the case card, the clock in a side column, the other team small in a corner, a hint shown big for 15 s; `/beheer/escape/tv` without a team is the leader's both-teams view. The escape screens poll with their own small script (`ESCAPESCRIPT`), not htmx: clocks and events ride as attributes of the polled block (`data-klokken`, `data-events`), so the block's inside only changes when something happened and the page swaps it only then (a landing post-it is not redrawn); it then plays Web Audio sounds for new rows in `escape_gebeurtenis`. The tv needs one click to allow sound. The alarm (theatre for too many tries on the lock) is an `alarm` event that only that team's room board acts on: `/beheer/escape/alarm` per team, or Q pressed twice within 600 ms on a room board (local only); a 5 s siren and red flashing overlay. `ZENDSCRIPT` gives sending an answer its 1.5 s "encrypted transmission" before the form posts.
- **Identity comes only from the `Remote-User` header** set by Caddy after Authelia; there is no login in the app. `Remote-Groups` decides leader access (groups `durfte-leiding` or `admins`): for `/beheer` and everything under it, for the menu and start page, and for leaders reading any saint on `/heilige/{qid}`. One SQLite connection serves all threads, so `db.py` puts every query behind one lock; blocking calls (Gemini) in async handlers go through `run_in_threadpool`. A player may read only their own three saints; leaders may read all. The container must have no published port, otherwise the header can be forged. `dev.py` fakes the headers from a cookie for local testing, binds 127.0.0.1, and must never be imported by `app.py` (tested). Server config (compose, Caddy, Authelia) lives in the separate `hopsakee-server` repo.
- **The repo is public.** No real names, e-mail addresses, children's names or secrets in code, data, docs or commit messages. Only quiz answers, never a username or nickname, go to the LLM. Log lines may name a failure but never contain the kid's text or the API key.

## Content rules

- **Design rules** (plan): nobody is shown up (every saint is presented positively), low barrier (a quiz takes at most 7 minutes on a phone), ownership (the kid chooses and says why), surprise (the explanation refers to what the kid wrote), life story rather than horror.
- **Texts are direct and kids may read them.** Saint texts are written under the `stijlregels` in `data/heiligen.json`: direct, no glossing over; 13-year-olds can handle a lot. Murder, sexual violence and martyrdom get one sentence saying that it happened, never how (not how the skin was stripped or how the lion started eating). Legend and history are labelled apart; disputed matters show both sides.
- **Kids read everything meant for their own use** (stories, background, words explained). Hide only what is addressed to leaders: `waarschuwing_voor_leiding`, `gespreksvraag`, `open_vragen`; `info()` in `app.py` decides what a kid sees. Whether a given app lets children read everything is a per-app choice; do not carry this decision to other apps.
- Every saint needs an image with maker and licence (`afbeelding.soort` is `heilige` or `tijd_en_streek`); images load from Wikimedia Commons unless a local copy exists in `data/afbeeldingen/`.
- Some existing records still go into more detail than the one-sentence rule allows (for example Josephine Bakhita and Catharina van Alexandrië). Treat those as texts to shorten when asked, not as a license to write more.
